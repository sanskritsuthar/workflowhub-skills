# Assessment criteria

Rate each criterion as strong, adequate, weak or unknown, with one line of
evidence. What counts as strong depends on the researcher's purpose; the
notes below say how.

## Fit

**Task fit.** Does the workflow do the analysis the researcher needs?
- Evidence: title, description, tags, topic or operation annotations.
- Strong: clearly designed for this analysis. Weak: a related analysis that
  would need substantial changes.

**Input and output fit.** Does it accept the researcher's data and produce
what they need?
- Evidence: declared inputs and outputs, formats, description.
- Unknown is common here. Say what would settle it, often a walkthrough with
  workflowhub-explain.

**Platform fit.** Can the researcher run it?
- Evidence: workflow type compared with the systems and computing
  environment the researcher has.
- Weak if it needs a system the researcher doesn't have and can't easily get.

## Reuse

**License.** Can the researcher reuse it for their purpose?
- Strong: a clear, recognised license compatible with the stated use. Weak
  or unknown: missing, unclear or restrictive.
- A missing license is a serious problem for publication or production use,
  even if it's acceptable for private exploration. Don't give legal advice;
  flag terms the researcher should check.

**Documentation.** Could the researcher understand and run it?
- Evidence: quality of the description, linked documentation, explained
  parameters, example or test data.

## Trust

**Maintenance.** Is it actively looked after?
- Evidence: maturity, number of versions, date of last update, activity in a
  linked source repository.
- Purpose matters. An unchanged but stable workflow can be fine for a
  well-established method; a stale work-in-progress workflow usually isn't.

**Credibility.** Who stands behind it?
- Evidence: owning team and creators, membership of curated community
  collections, DOI, linked publications, linked test results.
- A recognised team is a positive signal, not a guarantee.

## Practicalities

**Requirements.** What would running it take?
- Evidence: reference data or databases, containers or software
  environments, compute hints, platform-specific features.
- Often unknown from metadata alone. Record it as a question for
  workflowhub-explain.

## Overall verdict

- **Good fit:** no weak ratings on criteria that matter for the purpose.
- **Fit with caveats:** usable, with named issues to resolve first.
- **Poor fit:** a weak rating on a criterion that matters for the purpose.
- **Can't tell yet:** too many unknowns on criteria that matter. Say what
  would resolve them.
