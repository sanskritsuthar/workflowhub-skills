# Assessment criteria

Rate each criterion as strong, adequate, weak or unknown. Give one line of
evidence for each rating. The purpose of the researcher changes what is
strong. The notes below tell you how.

## Fit

**Task fit.** Does the workflow do the analysis that the researcher needs?
- Evidence: title, description, tags, topic or operation annotations.
- Strong: the authors made it for this analysis. Weak: it does a related
  analysis, and it needs large changes.

**Input and output fit.** Does it accept the data of the researcher, and
does it make what they need?
- Evidence: level 2 of the profile (what the user provides and the outputs,
  with formats), and the description.
- If you know the data of the researcher, examine the inputs that the data
  goes into. If the profile does not give their formats, read the workflow
  file.
- If not, unknown is frequent here. Tell the researcher what can supply the
  fact. This is frequently a walkthrough with workflowhub-explain.

**Platform fit.** Can the researcher run it?
- Evidence: the workflow type, compared with the systems and the computer
  environment that the researcher has.
- Weak if it needs a system that the researcher does not have and cannot
  get easily.

## Reuse

**License.** Can the researcher reuse it for their purpose?
- Strong: a clear, known license that agrees with the stated use. Weak or
  unknown: a missing, unclear or restrictive license.
- A missing license is a serious problem for publication or production use.
  For private exploration, it can be satisfactory. Do not give legal
  advice. Show the terms that the researcher must examine.

**Documentation.** Can the researcher understand and run it?
- Evidence: the quality of the description, linked documentation, explained
  parameters, example or test data, a diagram (the `docs` of the profile).

## Trust

**Maintenance.** Does a person look after it now?
- Evidence: maturity, number of versions, date of the last update, activity
  in a linked source repository.
- The purpose is important. A stable workflow without recent changes can be
  satisfactory for a well-known method. An old workflow that is still work in
  progress is usually not satisfactory.

**Credibility.** Who is responsible for it?
- Evidence: the team and the creators, membership of curated community
  collections, DOI, linked publications, linked test results.
- A known team is a good sign. It is not a guarantee.

## Practicalities

**Requirements.** What does a run need?
- Evidence: reference data or databases, containers or software
  environments, computer resources, features of the platform.
- Evidence: the level 2 requirements of the profile, and the tools that the
  authors list.
- Reference data is frequently visible only in step settings or parameters.
  If the purpose or the platform of the researcher depends on it, look
  there. If not, record it as a question for workflowhub-explain.

## Overall verdict

- **Good fit:** no weak ratings on the criteria that are important for the
  purpose.
- **Fit with caveats:** the researcher can use it, but must first solve the
  problems that you name.
- **Poor fit:** a weak rating on a criterion that is important for the
  purpose.
- **Can't tell yet:** too many unknowns on important criteria. Tell the
  researcher what can supply the missing facts.
